## Session — fix upload detection accuracy (low confidence on real potholes)

### User report
> "the pothole detection is not working properly when user uploaded it. or accuracy
> problem. it gives low for even potholes too."

### Root cause
The upload path never looked at the photo. `routes/uploads.js` had
`autoDetect()` — a stub returning `confidence 0.82` (images) / `0.79` (video),
`damage_class: 'pothole'` **always**, and `bbox_area_ratio: 0.25` **always**. With
`AUTO_VERIFY_CONFIDENCE = 0.85` every real pothole landed in Pending at 82 %, and a
blurred wall scored identically. The manual "Pothole" option was pinned at 0.82 too.

### Fix — `services/vision.js` (new, pure JS, no native build)
- Deps added: `jpeg-js`, `pngjs` (both pure JS; keeps the zero-native-build rule).
- Decode → block-average onto a ~192 px work canvas → two-scale local-mean
  background (near = rim detail, far = the interior of a frame-filling bowl) →
  dark-blob mask → largest 8-connected region → features: `coverage`, `fill`,
  `aspect`, `contrast`, Sobel `rim_edge` vs `interior_edge` ratio, `roadness`
  (grey/matte fraction), `sharpness`, `interiority` (border-contact penalty so a
  sky/grass horizon or shadowed wall corner is not read as a blob).
- Class heads are *gated* by real evidence (blob / patch / linearity) and
  multiplied by a pavement+focus context factor, so no-context frames cannot score
  on context alone. **All of this replaces the PRD's YOLOv8 claim — no ML runtime.
  Swap `analyzePixels` for a real model later; `analyzeUpload` is the stable contract.**
- Calibration: clear pothole ≥ 0.85 Verified · vague 0.60–0.84 Pending · junk < 0.60.
  Confidence and `bbox_area_ratio` are measured, so PRD 4.2 severity is real now.
- Undecodable frames (video/WebP/HEIC, > 64 MP) → `metadata-fallback` @ 0.62 Pending.

### Two design calls worth knowing
1. **Focus is measured at native resolution** (5 crops, take the sharpest), not on
   the work canvas: block averaging is resolution-dependent, and it made the same
   pothole score 0.97 at VGA but 0.63 at 12 MP.
2. **Below-gate citizen uploads are stored Pending, not discarded.** `ingestDetection`
   takes `{ holdBelowGate }`; the citizen/field upload routes pass `true` (the report
   page promises "held as Pending for a field officer", and the user asked for exactly
   that — see the report-map session above). The real confidence is still stored, so
   the officer sees the flag. The edge/dashcam stream is unchanged: still a 422.
